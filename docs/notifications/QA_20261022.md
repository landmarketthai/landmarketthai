## Retry, latency and cost

Eight attempts maximum. Exponential retry delays start at 30 seconds and respect valid Retry-After. Permanent errors are retained as failed. An ambiguous event is never automatically retried past 23 hours because LINE's key lasts 24 hours. `sent` records API acceptance, not guaranteed recipient delivery. See the [LINE contract](https://developers.line.biz/en/docs/messaging-api/retrying-api-request/).

First attempts use Next `after()` and target seconds, without a measured external latency guarantee. A daily Vercel backstop is included and needs no incoming traffic, but daily recovery can exceed the retry-key window and processes only three jobs per run. The current code therefore does **not** establish reliable near-real-time retries on Hobby. [Vercel documents Hobby's daily/hour-precision limit](https://vercel.com/docs/cron-jobs/usage-and-pricing).

Concrete options are documented in the [runbook](LINE_NOTIFICATIONS.md): verify an already compatible Vercel plan, approve free minute HTTP scheduling with an independent bearer secret, or evaluate Neon scheduled Functions after entitlement/cost verification. None was activated. Minute scheduling targets the next tick after backoff and offers about three attempts per minute for one schedule; no provider SLA is asserted.

Added recurring subscription cost: **$0 for the code/configuration itself**. Function invocations, Neon storage/compute and LINE OA message quota still count toward existing plans. Approximately 43,200 minute sweeps per 30 days can keep Neon compute warm, so total cost is unverified and may be nonzero. No service was purchased and no billing plan was changed.
